# face_select

구글 드라이브에 쌓인 사진 중 **내 얼굴이 들어간 사진만** 자동으로 골라내는 도구입니다.
원본은 건드리지 않고, 드라이브에 `내 얼굴 사진 (face_select)` 폴더를 만들어 **바로가기**를 모아 줍니다(추가 용량 0).

---

## 1. 전체 구조

```
 ┌────────────┐   ① enroll    ┌──────────────────────┐
 │ reference/ │ ────────────▶ │ 기준 임베딩 (N×512)   │  reference_embeddings.npy
 │ 내 사진 5~20장│              └──────────┬───────────┘
 └────────────┘                          │
                                         ▼ 코사인 유사도 비교
 ┌──────────────┐ ② scan  ┌───────────┐  ┌───────────────┐  ┌──────────────┐
 │ Google Drive │ ──────▶ │ 썸네일 다운 │─▶│ 얼굴 검출+임베딩 │─▶│ SQLite 캐시   │
 │ (Drive API)  │ 목록조회 │ (병렬 8개)  │  │ (InsightFace) │  │ 사진별 얼굴 벡터│
 └──────────────┘         └───────────┘  └───────────────┘  └──────┬───────┘
        ▲                                                          │
        │ ④ export: 결과 폴더 + 바로가기 생성        ③ report: CSV   │
        └──────────────────────────────────────────────────────────┘
```

| 단계 | 명령 | 하는 일 |
|---|---|---|
| ① 등록 | `enroll` | `reference/`의 내 사진에서 얼굴 임베딩을 뽑아 기준 세트로 저장 |
| ② 스캔 | `scan` | 드라이브 이미지를 받아 **모든 얼굴의 임베딩을 캐시에 저장** (이 단계가 가장 오래 걸림) |
| ③ 리포트 | `report` | 캐시된 임베딩과 기준 세트를 비교해 `match` / `review` CSV 생성 |
| ④ 내보내기 | `export` | 드라이브에 결과 폴더를 만들고 매칭된 사진의 바로가기 추가 |

## 2. 핵심 설계 결정

### 얼굴 인식 모델: InsightFace (`buffalo_l`: RetinaFace 검출 + ArcFace 인식)
- 얼굴을 512차원 벡터로 바꾸고, 같은 사람이면 코사인 유사도가 높게(≈0.5~0.9), 다른 사람이면 낮게(≈0~0.25) 나옵니다.
- `face_recognition`(dlib)보다 정확도가 높고, 측면·작은 얼굴·동양인 얼굴에서 특히 강합니다. CPU만으로도 동작합니다.
- ⚠️ `buffalo_l` 사전학습 모델은 **비상업적 용도**로만 배포됩니다. 개인 사진 정리 용도로는 문제없습니다.

### 원본 대신 썸네일로 분석
- Drive API의 `thumbnailLink` 뒤에 `=s1600`을 붙이면 긴 변 1600px JPEG를 받을 수 있습니다.
- 5~10MB 원본 대신 약 200~400KB만 받으므로 **전송량이 약 1/20로 줄고**, HEIC/RAW도 서버에서 JPEG로 변환해 주기 때문에 디코딩 문제도 사라집니다.
- 썸네일이 없으면 자동으로 원본을 받습니다. `--size 0`이면 항상 원본을 씁니다.

### "스캔"과 "판정"을 분리
- 스캔 단계에서는 **점수가 아니라 얼굴 임베딩 자체를 저장**합니다.
- 따라서 기준 사진을 추가하거나 임계값을 바꿔도 **다시 다운로드할 필요 없이** `report`만 다시 돌리면 몇 초 만에 결과가 갱신됩니다.
- 이미 처리한 사진은 `md5`로 확인해 건너뛰므로, 중간에 끊겨도 이어서 할 수 있고 새 사진만 증분 처리됩니다.

### 판정 방식
- 기준 사진을 여러 장 등록합니다(정면/측면, 안경 유무, 연도별 등).
- 사진 속 각 얼굴에 대해 `max(기준 임베딩과의 상위 3개 유사도 평균, 기준 중심점과의 유사도)`를 구하고, 사진 점수는 그중 최댓값입니다.
- `score ≥ threshold`(기본 0.40)면 `match`, 그보다 0.08 낮은 구간까지는 `review`(사람이 확인할 후보)로 분류합니다.
- 너무 작은 얼굴(< 40px)과 검출 신뢰도가 낮은 얼굴은 오탐의 주원인이므로 제외합니다.

### 권한 최소화
- OAuth scope는 `drive.readonly`(사진 읽기)와 `drive.file`(이 앱이 만든 폴더/바로가기만 쓰기)뿐입니다. 원본을 수정·삭제·이동하는 권한은 요청하지 않습니다.
- 모든 처리는 **내 컴퓨터에서** 이루어지며 얼굴 데이터가 외부 서버로 전송되지 않습니다.

## 3. 사용법

### 3-1. 준비
1. Python 3.10+ 설치 후:
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. **Google Cloud 설정** (최초 1회)
   1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트 생성
   2. "API 및 서비스 → 라이브러리"에서 **Google Drive API** 사용 설정
   3. "OAuth 동의 화면"을 외부/테스트 모드로 만들고 테스트 사용자에 내 계정 추가
   4. "사용자 인증 정보 → OAuth 클라이언트 ID → **데스크톱 앱**" 생성 후 JSON을 받아 프로젝트 루트에 `credentials.json`으로 저장
3. `reference/` 폴더에 **내 얼굴이 크게 나온 사진 5~20장**을 넣습니다. 여러 사람이 있는 사진이면 가장 큰 얼굴이 내 얼굴이어야 합니다.

### 3-2. 실행
```bash
python -m face_select enroll                    # ① 내 얼굴 등록
python -m face_select scan --limit 200          # ② 먼저 200장으로 시험 (처음 실행 시 브라우저 로그인 창이 뜸)
python -m face_select report                    # ③ output/my_photos.csv 확인 → 임계값 조정
python -m face_select scan                      # ② 전체 스캔 (중단해도 다시 실행하면 이어서 진행)
python -m face_select export --threshold 0.42   # ④ 드라이브에 결과 폴더 생성
```

자주 쓰는 옵션:
- `scan --folder <폴더ID>`: 특정 폴더(하위 폴더 포함)만 스캔. 폴더 ID는 드라이브 URL의 `folders/` 뒤 문자열
- `scan --workers 16`: 동시 다운로드 수 증가
- `--gpu`: NVIDIA GPU 사용 (`pip install onnxruntime-gpu` 필요)

### 3-3. 임계값 튜닝 팁
1. 200~500장 정도로 먼저 `scan` → `report` 실행
2. CSV를 `score` 순으로 보며 처음으로 남의 얼굴이 섞이기 시작하는 지점을 찾음
3. 그보다 약간 높게 `--threshold`를 잡음. 놓치는 사진이 많으면 `reference/`에 그런 사진(옆모습, 어릴 때 등)을 추가하고 `enroll` → `report`만 다시 실행

## 4. 예상 성능
| 항목 | 값 (대략) |
|---|---|
| CPU 처리 속도 | 사진당 0.3~0.6초 (8코어 기준) → 1만 장 ≈ 1~1.5시간 |
| GPU 처리 속도 | 사진당 0.03~0.05초 → 대부분 다운로드 속도가 병목 |
| 전송량 | 썸네일 기준 1만 장 ≈ 3GB |
| Drive API 한도 | 기본 할당량으로 충분하며, 429/5xx는 지수 백오프로 자동 재시도 |

## 5. 파일 구성
```
face_select/
  drive.py   # OAuth 인증, 이미지 목록(폴더 재귀), 썸네일/원본 다운로드, 결과 폴더·바로가기 생성
  faces.py   # 이미지 디코딩(EXIF 회전, HEIC), InsightFace 검출/임베딩, 기준 세트와 유사도 계산
  store.py   # SQLite 캐시 (photos / faces / exported 테이블)
  cli.py     # enroll / scan / report / export 명령
reference/   # 내 얼굴 기준 사진 (git에 올라가지 않음)
```
`credentials.json`, `token.json`, `cache.sqlite3`, `reference/` 내용은 `.gitignore`에 포함되어 커밋되지 않습니다.

## 6. 확장 아이디어
- **동영상**: 일정 간격으로 프레임을 추출해 같은 파이프라인 적용
- **여러 인물**: `reference/<이름>/` 구조로 가족별 앨범 자동 생성
- **클러스터링 기반 등록**: 기준 사진 없이 전체 얼굴을 클러스터링한 뒤 가장 큰 클러스터에서 "나"를 선택
- **리뷰 UI**: `review` 후보를 썸네일 그리드로 보여주고 클릭으로 확정 → 확정된 얼굴을 기준 세트에 추가(점진 학습)
- **Google Photos**: Photos Library API는 2025년부터 앱이 만든 항목만 읽을 수 있으므로, 구글 포토 사진은 Takeout으로 받아 로컬 폴더 모드로 처리하는 방식이 현실적
